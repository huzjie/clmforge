# clmforge 项目详细介绍（Introduction）

> 本文件是 clmforge 的**完整介绍文档**，面向想深入理解「对比式语言模型决策」这一
> 思路与工程实现的人。建议先读 README，再读本文。

## 1. 背景：为什么需要「对比式决策」

大语言模型做决策的主流方式是**生成式**：把候选动作拼进 prompt，让模型逐 token 输出
一个答案。这套范式有两个代价：

1. **延迟高**：每个决策都要跑一次完整的前向解码，token 一个接一个出。
2. **资源浪费**：为「选哪个工具」这种有界选择任务，模型依然跑完全部生成计算。

CLM（Contrastive Language Model）的思路是：**很多决策本质上是「在一组已知候选里挑
一个」，不需要生成，只需要打分**。于是把问题从「生成答案」变成「对比打分」。

## 2. 核心机制

### 2.1 共享嵌入空间

状态（上下文）和动作（候选）被编码到**同一个向量空间**：

- `e_s = StateEncoder(state)`
- `e_a = ActionEncoder(action)`

打分就是这两个向量的某种相似度：`score = head(e_s, e_a)`。

### 2.2 动作嵌入独立缓存（延迟来源）

关键洞察：动作与状态是**解耦**的。动作 `calc` 的嵌入不依赖当前状态，所以：

- 第一次遇到 `calc` → 编码并缓存
- 之后再遇到 `calc` → 直接取缓存，**零编码成本**

在一个「动作集合复用度高」的场景（工具路由、候选排序、校验），大量动作嵌入可复用，
延迟显著下降。这正是 1.6×–9× 加速的来源。

### 2.3 冻结主干 + 轻量可训练头

主干（如 Qwen3-8B）只负责产生嵌入，**冻结不训练**；只有打分头（linear / bilinear /
MLP）参与微调。这样：

- 微调成本极低，可自托管
- 冻结嵌入可离线预计算并缓存
- 训练稳定、易收敛

### 2.4 快/慢路由

不是所有决策都适合打分。引入**置信度 margin**（前两名分数差归一化）：

- margin 高 → 快路径（对比打分），几微秒出结果
- margin 低 → 回退慢路径（生成式），保证质量

这就是「把快速决策与昂贵推理分离」的工程落地。

## 3. 训练：对比学习

打分头用对比损失训练：

- **InfoNCE**：`-log(exp(s_p/τ) / Σ_j exp(s_j/τ))`，拉正样本分数、推负样本分数
- **Margin**：正样本分数要超过每个负样本至少 margin

训练数据形如 `(state, [action...], correct_key)`，正样本是 ground-truth 动作，其余
为 in-batch 负样本。

## 4. 工程实现要点

- **零依赖内核**：核心全部用标准库，`hash_embed` 用 MD5 派生确定性向量做「冻结主干」
  的零依赖替身；接入真实 encoder 只需覆写 `encode`。
- **确定性可训练 mock 后端**：`world_answer(state, actions)` 用 MD5 派生 ground-truth，
  mock 打分 = `skill·2·[is_correct] + noise`。训练上调 skill → 准确率单调上升，跨运行
  完全可复现。这是「能跑、能复现、不依赖外部服务」的关键。
- **内置 YAML 解析回退**：`utils/yamlish.py` 是极简 YAML 子集解析器，避免托管环境无
  `pyyaml` 时 CLI 直接挂掉。
- **动作缓存**：线程安全、FIFO 驱逐、可选持久化、命中率统计。

## 5. 适用场景与边界

**适合**：工具路由、候选排序、校验、游戏动作选择、检索重排等**有界选择**任务。

**不适合**：开放式生成、需要逐字推理的长链任务（这些应交给慢路径）。

## 6. 与已有方案的关系

- 对比 **生成式 agent 决策**（Jev 等）：CLM 用打分替代生成，动作嵌入缓存带来数量级延迟下降。
- 对比 **embedding 检索**：CLM 多了可训练打分头 + 快慢路由 + 对比训练，是「检索 + 决策」的上层。

## 7. 复现指南

```bash
python -m clmforge doctor                # 自检
python -m clmforge train --epochs 10     # 训练，看 skill 与准确率
python -m clmforge bench --n 200         # 五组基准
python -m clmforge speedup --n 500       # 延迟加速
python -m clmforge serve --port 8765     # HTTP 服务
```

详见 `docs/tutorials/` 与 `docs/api/`。
